# Handoff for a new machine or a new Claude chat

Read this first, then `docs/STAGE_PLAN.md` (the research plan). Several local planning files on the main
laptop (`AGENTS.md`, `CHAPTER_ROADMAP.md`, `Journal.md`, `KAGGLE_RUNS.md`, `IMPLEMENTATION_PLAN.md`) are
gitignored, so a fresh clone does not have them. Everything a new chat needs from them is summarised here.

## 1. Rules that always apply

- **Commits:** commit as the user (Satya Srinivas Paladugu) with their own git identity. **Never add
  `Co-Authored-By: Claude`, "Generated with Claude" or any AI attribution** to commits, PRs or files. This
  overrides any tool default.
- **The user's current explicit instruction wins** over this file and over the plan.
- **No private data or licensed assets in git:** no NoW or FaceScape images/scans, no model weights, no
  tokens, no heavy results. Executed notebooks that show dataset photos are not committed. FaceScape Kaggle
  datasets stay private; never share the FaceScape Drive link.
- **Only report measured results.** Proposed improvements are hypotheses. Do not claim a run succeeded until
  its outputs were downloaded and checked. Report partial coverage with counts.
- **Conserve usage** (Claude Pro): no polling loops, short outputs, run long commands in the background.
- Preserve user edits; don't silently replace baselines (RealDenseFace stays the first geometry baseline,
  ViT-S the default correction host, restoration is a control).
- Kaggle: the CLI cannot cancel runs — ask the user to cancel on the website. Max 2 GPU sessions per account.

## 4. Kaggle: how runs work (lessons already paid for)

- Accounts: **A = `satyapaladugu`** (Windows `kaggle` CLI), **B = `satyapaladuguplus`** (CLI inside WSL:
  `MSYS_NO_PATHCONV=1 wsl -d Ubuntu-26.04 -- /home/Satya/.venvs/semantic-kaggle/bin/kaggle`). On a new machine
  the user must set up `kaggle.json` for each account themselves; never handle their tokens.
- Image: torch 2.11 + cu130, Python 3.13, 2× T4. Set `docker_image_pinning_type: "original"` in every
  `kernel-metadata.json` so the image does not change under the cached wheels.
- **Custom CUDA builds:** nvdiffrast, RealDenseFace's FLAME solver extension and PyTorch3D are compiled for
  this exact image. Builds need `NVCC_APPEND_FLAGS=-static-global-template-stub=false` (CUDA ≥ 13) and
  `FORCE_CUDA=1` (both set in `setup.py`). Built wheels are cached in dataset `satyapaladugu/mesha-output`
  (`wheels/`); attach it and `setup.py` reports "installed from wheel". If Kaggle changes the image, rebuild and
  re-cache. These paths are CUDA-only: they do not run on CPU, TPU or integrated graphics.
- `setup.py` also: fetches the chumpy sdist and patches it on disk (numpy import, `getargspec`); finds weights
  by file name (Kaggle auto-extracts archives); installs git-lfs; downloads the MAE pretrain checkpoint and the
  DAViD matting model; pip installs yacs, iopath, fvcore, kornia, face_alignment, pyshtools.
- Appearance shims: `TORCH_FORCE_NO_WEIGHTS_ONLY_LOAD=1`, `face_alignment.LandmarksType._2D` alias, numpy
  aliases, DECA `extract_tex=True`; OpenDelight matting runs before `test.py`; use `Image.Resampling.BOX`.
- Notebook pattern: clone repo at a commit → `setup.main([...])` with an assertion on builds → find data under
  `/kaggle/input/**` with an assertion → one smoke job with an assertion → `runner.launch(...)` → summary with an
  assertion → `shutil.make_archive` of the output folder. Print the commit hash.
- Outputs: download with `kaggle kernels output <user>/<kernel> -p <dir>`; for big outputs, the user saves the
  output as a dataset and you download the dataset (`kaggle datasets download`). Extract only `runs/**`
  `*.json`, `neutral.obj`, `priors.npz` — the rest (repo copy, builds, weights) wastes disk.
- Pending: `satyapaladugu/trueface3d-prior-corrector` (notebook 13) → `out_PC.zip` with `gap_table.json`.

```powershell
cd TrueFace3D; py -3.12 -m venv .venv; .venv\Scripts\pip install -e .
```

Add numpy, trimesh, scipy, pandas, matplotlib, pillow, opencv-python, nbformat, nbconvert as needed (check
`pyproject.toml`). Jobs for this laptop: FaceScape download/subsetting, `docs/facescape_layout.md`,
`src/data_facescape.py`, `scripts/facescape_prepare.py`, degradation suite + tests, Kaggle dataset packaging,
CPU scoring of downloaded meshes, figures. Keep FaceScape data outside the repo (e.g. `D:\data\facescape`) and
point to it with an environment variable such as `TRUEFACE3D_FACESCAPE`.
